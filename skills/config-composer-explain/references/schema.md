# Configuration contract

Root: `$schema`, `defaultProfile`, `model`, `small_model`, `models`, `groups`, `agent`, `command`, `profiles`.

Groups: a map keyed by group name, with `{ description?, agent? }` values. Empty groups are valid for profile-only settings. Profiles: a map of `{ description?, permission?, model?, small_model?, models?, groups?: { [groupName]: { agent? } }, agent?, command? }`. All references and targets are exact names; structural errors and unknown names are invalid even in inactive profiles. Command settings use the root or profile's named `command` map.

Each native agent owns `groups: string[]`, in Markdown frontmatter or at `agent.<name>.groups` in native JSON, including built-ins. The array contains unique, nonempty exact group names; unknown groups fail composition. Missing membership means none, and `[]` explicitly clears it. The latest authored Markdown declaration replaces the whole previous declaration and takes priority over native JSON; an omitted later Markdown field leaves the previous declaration intact. Only the top-level native JSON field supplies JSON membership. `options.groups` does not supply membership. Composer removes its `groups` metadata before native agent use; it is not a provider option. Definition-map insertion order never reorders agent membership.

Agent patch: `model` or `modelRef` (mutually exclusive), `variant`, `temperature`, `top_p`, `steps`, `options`, `mode`, `permission`. `steps` is the native maximum number of agentic iterations, a positive safe integer; use this native name, not the deprecated `maxSteps`. Command patch: `agent`, `model`, `subtask`. No null unset operations in the document. Persisted null selection means None; missing selection follows `defaultProfile`.

Root and profile `models` are maps of exact alias names to `{ model: "provider/model", variant?, temperature?, top_p?, topK?, maxOutputTokens?, options? }`. Names must be nonempty and contain no NUL. Bindings cannot chain. Resolve each reference against root bindings with whole selected-profile binding replacement, including all parameter fields. A binding without `variant` writes the native default (`variant: ""`), clearing an earlier variant; an explicit referencing patch `variant` wins. Later groups or named patches can override either field, and frontmatter is final. Ordinary concrete `model` patches retain independent variant inheritance.

`modelRef` exists only in Composer group and named agent patches, including profile patches. It is resolved before native materialization and never becomes a native field or provider option. Root bindings apply in Shared only. A name defined only in profiles contributes no model, variant or parameters in Shared only, even when the reference has an explicit variant; unrelated patch fields still apply. In a selected profile, every consumed reference needs a binding in that profile or at root; a binding in another profile is insufficient. Unknown alias names fail validation everywhere. Errors identify the reference pointer and missing alias/profile. Unused group references do not require selected-profile bindings.

Model-bound parameters are request defaults, applied only when the actual provider/model matches the binding. `temperature` is 0–2, `top_p` is 0–1, and `topK`/`maxOutputTokens` are positive safe integers. For example: `{ "model": "anthropic/claude-sonnet-4-5", "temperature": 0.2, "maxOutputTokens": 4096, "options": { "thinking": { "type": "disabled" } } }`. Composer passes user-supplied parameters through without filtering by provider adapter or model capability metadata. Users choose parameters supported by their provider/model; downstream adapters may reject or ignore unsupported values. Provider options retain the native adapter's meaning and support. Put sampling/output controls in their binding fields, not raw `options` keys.

Explicit resolved agent `temperature`/`top_p` override binding defaults, including zero. Explicit agent option leaves and the selected native variant's option leaves override binding options; authored frontmatter `options`, including `{}`, blocks the entire binding options field. Every later alias replaces the parameter bundle, even for the same model; a later concrete model clears it. A frontmatter model pin to the same model retains independent defaults, while a different model pin clears them. Omitted parameters preserve native request defaults. Manual/session/caller selections of another model receive none of the binding parameters. `/view-configs` shows these conditional defaults and their source separately from native agent fields.

Precedence: supplied native fields → selected profile general `permission` → each agent-owned group with its selected profile patch, in membership order → root named patches → profile named patches → actual authored agent frontmatter. A later group wins even over an earlier group's profile patch. Authored options remain whole-field pins, including empty options. Authored `steps` is final. Like the host, a Markdown file's deprecated `maxSteps` counts as that file's `steps` when it omits `steps`. Permissions combine using the rules below; frontmatter permission rules apply last. Later Markdown sources still determine the effective authored field before composition. Native bodies are never edited.

Permission order: native global policy → native agent policy → selected profile `permission` → each shared/profile group pair in membership order → root named agent → profile named agent → authored frontmatter. Profile permissions cover every known agent, including built-ins and agents without groups; they do not rewrite native global configuration. Unrelated native defaults remain host-owned. Shared only omits the profile layer.

Permission merging follows native ordered tool maps. Each touched tool block moves to the end, carrying its retained patterns. Within a block, distinct patterns remain; an exact duplicate is deleted then appended with the incoming action. A scalar tool action is its `"*"` pattern; a scalar whole policy is the `"*"` tool. Empty top-level permission maps add no rules. A later catch-all overrides earlier matching entries in the resulting map. This is block-level composition, not a chronological list of every individual rule across layers.

For example, three groups declaring `{ "task": { "alpha": "allow" } }`, then `{ "*": "deny" }`, then `{ "task": { "beta": "allow" } }` produce `{ "*": "deny", "task": { "alpha": "allow", "beta": "allow" } }`. Both Task targets are allowed because the last group moves the combined Task block after the wildcard. Two groups with separate Task allowlists combine; repeating a Task `"*": "deny"` in the later block places that catch-all after earlier grants. Frontmatter rules follow the same merge and are always applied last; `permission: {}` adds nothing, while `permission: deny` appends the final wildcard denial.

Authored frontmatter is final even over a conflicting later native JSON value. `/view-configs` shows the authored source and blocked Composer candidate where attribution matches the loaded contribution. Same-batch duplicate native identities and unsupported frontmatter engines or metadata stop composition with a source diagnostic. Correct the native input and restart the OpenCode server process. Failed bootstrap can prevent profile switching; inspection still shows available native values without claiming complete Composer attribution. Normalized host defaults cannot substitute for exact authored authority.

One source defaults to the configuration directory's `config-composer.jsonc`; optional `configFile` is absolute or relative to that directory. Missing implicit source is empty; missing explicit or invalid definitions remain startup errors until server restart. No source stacking. The loaded document, options, source and external selection locator are captured once per directory/worktree in the server process. File edits, deletion and source retargeting do not change that capture.

`/profiles` directly offers Follow configured default, Shared only and loaded named profiles, with preview and one Apply confirmation. The selection is persisted separately per canonical source/worktree; it never changes JSONC definitions. `/view-configs` is read-only inspection of loaded definitions, membership, origins, agent frontmatter pins, overridden values, permission contributions before frontmatter and effective native values. Pending saved choices remain in `/profiles`. Inspection does not read current definition/native files. Restart the OpenCode server process after file edits; reconnecting the TUI does not reset the capture.

Applying uses the idle native instance lifecycle. Directly observed native JSON, agent metadata/body or command edits block profile switching with a restart instruction. These observations are not a complete dependency graph of native includes, environment or other plugins. Composer does not replay native bodies or provider/session configuration. Busy or failed application remains saved and pending; confirmation requires the same loaded definition and selection identity after disposal. Existing session model/variant selections remain native.
