---
name: config-composer-create
description: Create a shared Config Composer definition file for existing native agents and commands.
---

Read the current definition and native target names before editing. Use the packaged schema and [review example](examples/review.jsonc). Ask for the destination if it is not known. Do not create or rewrite native prompt bodies.

Author one JSONC file with optional `groups`, `agent`, `command`, `model`, `small_model`, `models`, `profiles`, and `defaultProfile`. Groups are a name-keyed map of `{ description?, agent? }` settings. Each native agent owns an ordered `groups` array in Markdown frontmatter or at `agent.<name>.groups` in native JSON. Group definitions never contain member lists. Missing membership means no groups; an empty array clears membership. A raw Markdown declaration takes priority over native JSON membership. Profile `groups` references root names and may patch agent settings without changing membership. Apply each group and its selected profile patch together, following the agent's order; later entries win overlaps. Named agent and command settings remain available at the root and in profiles. One profile can be selected per worktree. Validate inactive profiles too.

Root and profile `models` map aliases to `{ model: "provider/model", variant?: string }`. A profile binding replaces the entire matching root binding. Use `modelRef` only in Composer group or named agent patches, mutually exclusive with `model`. A binding without `variant` clears an inherited variant to native default; explicit referencing `variant`, later patches and frontmatter still win. Concrete model patches preserve independent variant inheritance. Aliases never reference other aliases. Unknown names are invalid even in inactive definitions. In Shared only, a profile-only alias contributes neither model nor variant, including an explicit referencing variant; other patch fields still apply. Every consumed reference in a selected profile needs a root or selected-profile binding.

Authored native agent frontmatter always overrides Composer settings, including literal empty values. Options replace the entire field. Permission objects replace exact tool blocks; frontmatter permission replaces the whole policy. Never invent a command variant or put model aliases in native configuration or provider options.

Use `/profiles` for a direct worktree choice: Follow configured default, Shared only, or a named loaded profile. Preview and Apply while idle. `/view-configs` inspects loaded shared groups, every loaded profile, source origins, final raw pins and verified applied values. Definitions are captured once per directory/worktree in the server process; edit the file externally and restart the OpenCode server process to load changes. Selection is persisted separately and never written into the definition file. A switch blocked by observed native file changes requires restart. Failed application remains saved and pending. Existing session model/variant choices can remain retained.
